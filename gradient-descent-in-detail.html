Gradient Descent in Detail

Gradient descent is the engine behind nearly every machine learning model trained today. It answers one question: given a function measuring how wrong our model is, which direction should we nudge the parameters to make it less wrong? This note builds the intuition, derives the math, and walks through every practical variant you'll encounter in the wild.

The Core Intuition

Imagine you're blindfolded on a hilly landscape and you want to reach the lowest valley. You can't see the whole landscape — you can only feel the slope under your feet. The strategy is simple: always step in the direction that goes downhill. That's gradient descent.

In machine learning, the "landscape" is the loss surface — a high-dimensional function mapping model parameters θ to a scalar error. The "slope" is the gradient ∇L(θ).

Figure 1 — Gradient descent navigates the loss surface by following the negative gradient

The Mathematics

Given a loss function L(θ) and current parameters θ, the update rule is:

θ  ←  θ  −  α · ∇θL(θ)
θ = model parameters α = learning rate ∇L(θ) = gradient of loss

The gradient ∇L(θ) is a vector of partial derivatives — one per parameter. It points in the direction of steepest ascent. We subtract it (hence negative gradient) to go downhill.

A Worked Example

Suppose our loss is simply L(θ) = θ². The gradient is dL/dθ = 2θ. Starting at θ = 4 with α = 0.1:

python
theta = 4.0
alpha = 0.1

for step in range(10):
    loss     = theta ** 2
    gradient = 2 * theta          # dL/dθ
    theta    = theta - alpha * gradient
    print(f"step {step+1:2d}: θ={theta:.4f}  L={theta**2:.4f}")

# step  1: θ=3.2000  L=10.2400
# step  2: θ=2.5600  L=6.5536
# ...converges toward θ=0 (minimum)

The Three Variants

The key difference between variants is how many samples you use to estimate the gradient at each step.

Figure 2 — The three gradient descent variants differ only in batch size. Mini-batch is the default in practice.

The Learning Rate: Everything Depends On It

The learning rate α controls how big each step is. Too small and training takes forever; too large and you overshoot the minimum and diverge.

Figure 3 — Learning rate is the most important hyperparameter: too small wastes time, too large causes divergence

Advanced Optimizers

Plain SGD suffers from slow convergence and sensitivity to the learning rate. Modern optimizers fix this by adapting the step size for each parameter automatically.

Momentum

Keeps a running average of past gradients (a "velocity"), so the update smooths out noisy oscillations and accelerates in consistent directions.

python
# Momentum SGD — manual implementation
velocity = 0
beta     = 0.9   # momentum coefficient
alpha    = 0.01  # learning rate

for grad in gradients:
    velocity = beta * velocity + (1 - beta) * grad
    theta   -= alpha * velocity

Adam (Adaptive Moment Estimation)

Adam combines momentum (1st moment) with per-parameter learning rate scaling (2nd moment). It's the default optimizer for almost every deep learning project.

python
# Adam — manual implementation
import numpy as np

m, v = 0, 0          # 1st & 2nd moment estimates
beta1, beta2 = 0.9, 0.999
alpha, eps   = 1e-3, 1e-8

for t, grad in enumerate(gradients, 1):
    m = beta1 * m + (1 - beta1) * grad           # biased 1st moment
    v = beta2 * v + (1 - beta2) * grad ** 2       # biased 2nd moment
    m_hat = m / (1 - beta1 ** t)                   # bias-corrected
    v_hat = v / (1 - beta2 ** t)
    theta -= alpha * m_hat / (np.sqrt(v_hat) + eps)

Full Training Loop in PyTorch

python
import torch, torch.nn as nn
from torch.utils.data import DataLoader, TensorDataset

# Toy dataset
X = torch.randn(1000, 10)
y = torch.randn(1000, 1)
loader = DataLoader(TensorDataset(X, y), batch_size=32, shuffle=True)

# Model + optimizer
model = nn.Sequential(nn.Linear(10, 64), nn.ReLU(), nn.Linear(64, 1))
opt   = torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=1e-4)
loss_fn = nn.MSELoss()

for epoch in range(20):
    epoch_loss = 0
    for xb, yb in loader:
        pred = model(xb)            # forward pass
        loss = loss_fn(pred, yb)    # compute loss
        opt.zero_grad()             # clear old gradients
        loss.backward()             # backprop → compute ∇L
        opt.step()                  # θ ← θ − α∇L
        epoch_loss += loss.item()
    print(f"Epoch {epoch+1:2d} | loss {epoch_loss/len(loader):.4f}")

Learning Rate Schedules

A fixed learning rate is rarely optimal. Schedules decay it over time so early training makes large, exploratory steps and later training makes fine, precise ones.

python
# Cosine annealing — smoothly decays to a minimum LR
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    opt, T_max=20, eta_min=1e-6
)

for epoch in range(20):
    train_one_epoch(model, loader, opt, loss_fn)
    scheduler.step()
    print(f"LR: {scheduler.get_last_lr()[0]:.2e}")

Common Pitfalls

  • Vanishing gradients — in deep networks, gradients shrink to near-zero in early layers. Fix: use ReLU activations, batch normalisation, residual connections.
  • Exploding gradients — gradients grow unboundedly. Fix: gradient clipping (torch.nn.utils.clip_grad_norm_).
  • Stuck in local minima — less of a problem in high-dimensional spaces than people think; saddle points are more common. Fix: SGD noise helps escape.
  • Not zero-ing gradients — PyTorch accumulates gradients by default. Always call optimizer.zero_grad() before loss.backward().
  • Learning rate too high at start — use learning rate warmup for transformers and large models.
Rule of thumb

Start with Adam at lr=1e-3. If it diverges, try 1e-4. If it's too slow, try 3e-3. Use a cosine schedule for fine-tuning.
