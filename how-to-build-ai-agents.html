How to Build AI Agents

An AI agent is a program that uses a language model as its brain — in a loop. It receives a task, thinks, calls tools, observes results, and repeats until done. This note walks through what that actually means in code, from a bare loop to a production-ready system.

What is an AI Agent?

The term "agent" gets overloaded. At its core, an agent is a loop: a language model that can take actions via tools, observe results, and decide what to do next — without a human in the middle.

Agent = LLM + Tools + Loop

ComponentRoleExample
LLMReasoning engineClaude, GPT-4o, Llama 3
ToolsActions in the worldweb_search, run_code, read_file
MemoryContext persistenceMessage history, vector store
LoopOrchestrationwhile not done: think → act → observe

The Agent Loop

Every agent runs some version of this loop. The LLM sees the conversation history plus tool results, produces a response (which may include tool calls), you execute those tools, append the results, and repeat until the model stops requesting tools.

User: What's the weather in SF and the top HN story today?

Agent: I need two things. Let me call tools.
→ get_weather("San Francisco")
result: "16°C, partly cloudy"
→ fetch_url("https://news.ycombinator.com")
result: "Top: 'We built an agent in 50 lines' ..."

Agent: SF is 16 °C and partly cloudy. The top HN story is…

Step 1 — Define Your Tools

Tools are functions your agent can call. You describe each tool's schema so the LLM knows when and how to use it.

python
# tools.py
import httpx, json

def web_search(query: str) -> str:
    """Search the web and return top results."""
    resp = httpx.get(f"https://api.duckduckgo.com/?q={query}&format=json")
    results = resp.json().get("RelatedTopics", [])[:3]
    return json.dumps([r.get("Text") for r in results])

TOOLS = [{
    "name": "web_search",
    "description": "Search the web for up-to-date information.",
    "input_schema": {
        "type": "object",
        "properties": {"query": {"type": "string"}},
        "required": ["query"]
    }
}]
TOOL_MAP = {"web_search": web_search}

Step 2 — Write the Agent Loop

python
# agent.py
import anthropic
from tools import TOOLS, TOOL_MAP

client = anthropic.Anthropic()

def run_agent(task: str, max_iter: int = 10) -> str:
    messages = [{"role": "user", "content": task}]

    for _ in range(max_iter):
        response = client.messages.create(
            model="claude-sonnet-4-6",
            max_tokens=4096,
            tools=TOOLS,
            messages=messages,
        )
        if response.stop_reason != "tool_use":
            return next(b.text for b in response.content if b.type == "text")

        messages.append({"role": "assistant", "content": response.content})
        tool_results = []
        for block in response.content:
            if block.type != "tool_use": continue
            try:
                result = TOOL_MAP[block.name](**block.input)
            except Exception as e:
                result = f"Error: {e}"
            tool_results.append({
                "type": "tool_result",
                "tool_use_id": block.id,
                "content": result,
            })
        messages.append({"role": "user", "content": tool_results})

    return "Max iterations reached."
Key insight

That loop above is the complete agent. Everything else — memory, streaming, planning — is layered on top of this core pattern.

Step 3 — Add a System Prompt

A system prompt shapes the agent's persona, tool preferences, output format, and constraints.

python
SYSTEM = """You are a research agent. Answer questions accurately using tools.
- Always search before stating facts
- Cite sources when possible
- If a tool fails, try an alternative approach
- Be concise: one paragraph per topic
"""

response = client.messages.create(
    model="claude-sonnet-4-6",
    system=SYSTEM,
    max_tokens=4096,
    tools=TOOLS,
    messages=messages,
)

Step 4 — Multi-Step Planning with LangGraph

For complex tasks, wire up agents as a directed graph. Each node does one thing; edges control flow.

python
from langgraph.graph import StateGraph, END
from typing import TypedDict, Annotated
import operator

class AgentState(TypedDict):
    messages: Annotated[list, operator.add]
    task: str
    plan: str
    result: str

def planner_node(state):
    return {"plan": llm.invoke(f"Plan: {state['task']}")}

def executor_node(state):
    return {"result": run_agent(state["plan"])}

graph = StateGraph(AgentState)
graph.add_node("planner",  planner_node)
graph.add_node("executor", executor_node)
graph.set_entry_point("planner")
graph.add_edge("planner", "executor")
graph.add_edge("executor", END)
app = graph.compile()

Step 5 — Streaming via FastAPI SSE

Stream agent output token-by-token using Server-Sent Events so users don't stare at a blank screen.

python
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse
import json

app = FastAPI()

async def _sse(event: str, data: dict) -> str:
    return f"event: {event}\ndata: {json.dumps(data)}\n\n"

@app.post("/run")
async def run_endpoint(request: Request):
    body = await request.json()

    async def stream():
        with client.messages.stream(
            model="claude-sonnet-4-6",
            max_tokens=4096,
            messages=[{"role": "user", "content": body["task"]}]
        ) as s:
            async for text in s.text_stream:
                yield await _sse("token", {"text": text})
            yield await _sse("done", {})

    return StreamingResponse(stream(), media_type="text/event-stream")

Production Checklist

  • Always set max_iterations — models can loop indefinitely
  • Wrap every tool call in try/except and return an error string
  • Log all LLM requests and tool results for debugging
  • Add per-tool timeouts (e.g., 30 s)
  • Stream output — don't make users wait for the full response
  • Cap max_tokens per task type
  • Trim old message turns to avoid context overflow
Warning

Without a max_iterations guard a confused agent loops until you hit a rate limit or drain your API budget.
