PCA Understanding

Real-world datasets have hundreds or thousands of features. Most of that information is redundant — many features are correlated and can be summarised by fewer variables without meaningful loss. Principal Component Analysis (PCA) finds those directions of maximum variance and projects your data onto them. This note explains the geometry, the math, and the code.

The Problem: Too Many Dimensions

When data has many features, three bad things happen: models overfit, distances become meaningless (the "curse of dimensionality"), and visualisation becomes impossible. PCA compresses the data into a lower-dimensional representation that preserves as much variance as possible.

Figure 1 — PCA compresses correlated high-dimensional features into a small set of uncorrelated principal components

The Geometric Intuition

PCA finds the axes (principal components) along which the data varies the most. The first principal component (PC1) is the line through the data cloud that minimises the total squared distance from each point to the line — equivalently, maximises the variance of the projected points. PC2 is the next best axis, constrained to be perpendicular to PC1, and so on.

Figure 2 — PC1 captures maximum variance (the "long axis" of the cloud); PC2 is orthogonal and captures remaining variance

The Algorithm: Step by Step

Figure 3 — The five-step PCA algorithm from raw data to reduced representation

PCA from Scratch in NumPy

python
import numpy as np

def pca(X: np.ndarray, k: int) -> tuple:
    """
    Principal Component Analysis from scratch.
    X : (n, p) data matrix
    k : number of components to keep
    Returns: Z (projected data), W (component matrix), explained_variance_ratio
    """
    # ① Centre the data
    X_c = X - X.mean(axis=0)

    # ② Covariance matrix  (p × p)
    cov = (X_c.T @ X_c) / (X_c.shape[0] - 1)

    # ③ Eigendecomposition
    eigenvalues, eigenvectors = np.linalg.eigh(cov)

    # ④ Sort descending & pick top k
    order = np.argsort(eigenvalues)[::-1]
    eigenvalues  = eigenvalues[order]
    eigenvectors = eigenvectors[:, order]
    W = eigenvectors[:, :k]           # (p, k) projection matrix

    # ⑤ Project onto k components
    Z = X_c @ W                       # (n, k)

    explained = eigenvalues[:k] / eigenvalues.sum()
    return Z, W, explained

# ── Example ──────────────────────────────────────────────
np.random.seed(42)
X = np.random.randn(200, 10)   # 200 samples, 10 features

Z, W, evr = pca(X, k=2)

print(f"Original shape : {X.shape}")       # (200, 10)
print(f"Reduced shape  : {Z.shape}")       # (200, 2)
print(f"Explained var  : {evr.sum():.1%}") # ~20% (random data)

PCA with scikit-learn

python
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler
from sklearn.datasets import load_digits
import matplotlib.pyplot as plt

# Load 64-feature digit images
digits = load_digits()
X, y   = digits.data, digits.target      # (1797, 64)

# Always scale before PCA!
X_scaled = StandardScaler().fit_transform(X)

# ── How many components to keep? ─────────────────────────
pca_full = PCA().fit(X_scaled)
cumvar   = pca_full.explained_variance_ratio_.cumsum()
n_95     = (cumvar >= 0.95).argmax() + 1
print(f"Components for 95% variance: {n_95}")  # ~29

# ── Reduce to 2D for visualisation ───────────────────────
pca_2d = PCA(n_components=2, random_state=42)
Z = pca_2d.fit_transform(X_scaled)

print(f"Explained (2 PCs): {pca_2d.explained_variance_ratio_.sum():.1%}")

plt.figure(figsize=(8, 6))
scatter = plt.scatter(Z[:, 0], Z[:, 1], c=y, cmap="tab10", s=15, alpha=0.7)
plt.colorbar(scatter, label="Digit class")
plt.xlabel("PC 1"); plt.ylabel("PC 2")
plt.title("MNIST digits projected to 2D via PCA")
plt.tight_layout(); plt.show()

Choosing the Number of Components

Plot the cumulative explained variance ratio and pick the "elbow" — the point where adding another component brings diminishing returns.

python
plt.plot(range(1, len(cumvar) + 1), cumvar, marker="o", ms=3)
plt.axhline(0.95, color="red", linestyle="--", label="95% threshold")
plt.axvline(n_95,  color="red", linestyle="--")
plt.xlabel("Number of components")
plt.ylabel("Cumulative explained variance")
plt.legend(); plt.tight_layout(); plt.show()
Figure 4 — The scree plot shows how much variance each additional component captures; choose k where the curve flattens

When to Use PCA

Use PCA when…Avoid PCA when…
Features are highly correlatedFeatures are already low-dimensional
You need 2D/3D visualisationYou need interpretable features
Training is slow due to many featuresNon-linear structure is important (use t-SNE / UMAP)
Removing noise before downstream MLData has categorical features
Preprocessing for clusteringClass separation is the primary goal (use LDA)
Important

Always standardise your features (zero mean, unit variance) before PCA. Features on larger scales will dominate the principal components otherwise.

PCA vs. Other Dimensionality Reduction Methods

MethodLinear?Best forSpeed
PCAYesGeneral preprocessing, noise removalFast
t-SNENoCluster visualisationSlow
UMAPNoLarge-scale visualisation, preserves structureMedium
LDAYesSupervised class separationFast
AutoencoderNoComplex non-linear compressionSlow (training)

Common Pitfalls

  • Forgetting to scale — features in metres vs. kilometres give wildly different PCs. Always StandardScaler first.
  • Fitting on the test set — fit the PCA on training data only, then transform both train and test.
  • Keeping too few components — if you keep only 2 PCs for a downstream classifier, you might lose discriminative signal. Check accuracy vs. k.
  • Using PCA for non-linear data — Swiss roll, concentric circles, and manifolds need t-SNE or UMAP.
  • Interpreting PCs as features — PCs are linear combinations of all original features. They're hard to explain to stakeholders.
Pipeline tip

In scikit-learn, use Pipeline([('scaler', StandardScaler()), ('pca', PCA(n_components=0.95)), ('clf', ...)]) to chain scaling → PCA → model in one object that cross-validates correctly.
