Introduction to Retrieval-Augmented Generation

LLMs know a lot — but their knowledge is frozen at training time and they can't see your private documents. RAG fixes both problems by retrieving relevant context at inference time and injecting it into the prompt. This note explains how it works, how to build it, and how to make it production-ready.

The Core Problem RAG Solves

A language model trained in mid-2024 knows nothing about your internal wiki, last week's support tickets, or the PDF your colleague sent this morning. You have three options:

  • Fine-tuning — retrain the model on your data. Expensive, slow, and the model still hallucinates facts.
  • Stuffing context — paste all documents into the prompt. Works for small corpora; breaks at scale.
  • RAG — search your documents at query time, pull only the relevant chunks, let the LLM reason over real evidence.
Definition

Retrieval-Augmented Generation (RAG) = search a knowledge base for relevant passages, insert them into the prompt, then generate a grounded answer.

The Two Pipelines

RAG has two distinct phases that run at different times:

Figure 1 — Indexing (offline, run once) vs. Retrieval (online, per query)

Pipeline 1: Indexing

Indexing transforms raw documents into a searchable vector index. It runs offline — once per knowledge base update.

Chunking with Overlap

Documents are too long to embed whole. Split into chunks of 200–500 tokens with 10–20% overlap so no fact falls at a boundary seam.

Figure 2 — Chunking with overlap prevents facts from falling at boundary seams

Pipeline 2: Retrieval & Generation

At query time the user's query is embedded with the same model used during indexing — this is critical. You find the top-k nearest chunks by cosine similarity, inject them into the prompt, and let the LLM answer.

Building It: Full Code

Install dependencies

bash
pip install llama-index llama-index-embeddings-ollama \
            llama-index-llms-ollama chromadb

Indexing pipeline

python
# index.py  —  run once to build the vector store
from llama_index.core import SimpleDirectoryReader, VectorStoreIndex, Settings
from llama_index.embeddings.ollama import OllamaEmbedding
from llama_index.llms.ollama import Ollama
from llama_index.vector_stores.chroma import ChromaVectorStore
from llama_index.core import StorageContext
import chromadb

Settings.embed_model   = OllamaEmbedding(model_name="nomic-embed-text")
Settings.llm           = Ollama(model="llama3.2", request_timeout=120)
Settings.chunk_size    = 512
Settings.chunk_overlap = 64

documents = SimpleDirectoryReader("./docs").load_data()
print(f"Loaded {len(documents)} document(s)")

db                = chromadb.PersistentClient(path="./chroma_db")
chroma_collection = db.get_or_create_collection("my_rag")
vector_store      = ChromaVectorStore(chroma_collection=chroma_collection)
storage_context   = StorageContext.from_defaults(vector_store=vector_store)

index = VectorStoreIndex.from_documents(
    documents, storage_context=storage_context, show_progress=True
)
print("✓ Index built and persisted to ./chroma_db")

Query pipeline

python
# query.py
from llama_index.core import VectorStoreIndex, Settings
from llama_index.embeddings.ollama import OllamaEmbedding
from llama_index.llms.ollama import Ollama
from llama_index.vector_stores.chroma import ChromaVectorStore
from llama_index.core import StorageContext
import chromadb

Settings.embed_model = OllamaEmbedding(model_name="nomic-embed-text")
Settings.llm         = Ollama(model="llama3.2", request_timeout=120)

db              = chromadb.PersistentClient(path="./chroma_db")
vector_store    = ChromaVectorStore(chroma_collection=db.get_collection("my_rag"))
storage_context = StorageContext.from_defaults(vector_store=vector_store)
index           = VectorStoreIndex.from_vector_store(vector_store, storage_context=storage_context)

query_engine = index.as_query_engine(
    similarity_top_k=5,
    streaming=True,
    response_mode="compact",
)

response = query_engine.query("What is the refund policy?")
response.print_response_stream()

for node in response.source_nodes:
    print(f"\n[score={node.score:.3f}] {node.text[:120]}…")
$ python query.py

According to the policy, customers may request a full refund within 30 days. After 30 days, store credit is offered at the support team's discretion…

[score=0.874] "Refund requests after 30 days will be reviewed on a case-by-case basis…"

Common Pitfalls

  • Wrong embedding model at query time — use the exact same model that indexed the chunks.
  • Chunks too large — big chunks hurt precision; irrelevant text around the answer confuses the LLM.
  • Chunks too small — tiny chunks lose surrounding context needed to understand the answer.
  • No overlap — facts at chunk boundaries become unretrieval.
  • Retrieving too few chunks — k=1 is fragile; use 3–8.
  • Stale content — add a last_updated metadata field and filter on it.
